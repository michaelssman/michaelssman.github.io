# 阿里云短信认证接入准备

本文面向第一次接入短信验证码的 Java 开发者，只完成 **PNVS 服务开通、费用确认、RAM 权限和后端凭据准备**。不包含注册登录代码，也不定义项目的账号表、接口路径、Token 或重置密码策略；这些应放在各项目的实现文档。

## 1. 先分清产品与准备材料

- SMS（Short Message Service，短消息服务）是短信传输方式。短信验证码是 OTP（One-Time Password，一次性密码）的一种，用来核验本次能否接收指定手机号的消息，不等于实名身份或完整账号安全。
- PNVS（Phone Number Verification Service，号码认证服务）中的“短信认证”，提供发送与核验验证码 API。它与普通短信产品不是同一套接口、模板和套餐。
- RAM（Resource Access Management，访问控制）用于给程序授予必要权限。AccessKey 是程序调用云 API 的凭据；不要使用阿里云主账号密钥，也不要将凭据放入 App 或网页。

准备可管理 RAM 和目标 ECS 的阿里云账号、实名认证、少量测试预算，以及仅自己可访问的凭据保存位置。本文的控制台步骤在浏览器中执行；完成前先保持项目短信发送开关关闭。账号与登录的基础区别见[认证和授权](认证和授权.md#authentication-authorization)。

## 2. 开通服务并确认费用

1. 登录[号码认证控制台](https://dypns.console.aliyun.com/)，完成账号实名认证，按页面条款确认开通。官方新手流程要求开启短信认证和融合认证功能；仅使用短信 API 时，不要因此把其他登录方案的客户端 SDK 一并引入项目。[官方开通指引](https://help.aliyun.com/zh/pnvs/getting-started/sms-authentication-service-novice-guide)
2. 打开短信认证概览，确认服务可用，再查看“短信认证（API 版本）”的价格、余额及套餐余量。本文不固定单价；测试短信也会计费，核验免费，发送费用按运营商回执规则结算。普通短信服务套餐与短信认证套餐额度不互通。[计费规则](https://help.aliyun.com/zh/pnvs/product-overview/product-pricing/)
3. 在控制台设置可用的余额或套餐余量提醒，并限制第一次联调次数。应用自己的每日发送额度与云账户总账单不是同一件事，其他程序和控制台发送也可能产生费用。

检查结果：控制台显示服务已开通，已确认使用的是短信认证 API 产品和对应计费规则。此时不必点击发送测试短信，也不能把“已经开通”写成“真实发送已验收”。

## 3. 选择签名与模板

1. 进入“短信认证参数配置”，在赠送签名配置中选择一个实际可用的签名，记下名称。签名是短信中的发送方展示标识，不是密码或数字签名。
2. 打开赠送模板配置，按实际用途选择模板，记录模板 Code（模板编号）及变量要求。登录、重置密码等用途应由后端入口决定，不让客户端任意指定模板。
3. 系统赠送签名应搭配系统赠送模板。“赠送”指提供可用签名和模板，不表示发送免费。模板编号与业务场景的具体对应关系写在项目配置中，不把某一个项目的选择当成所有系统的固定配置。[签名与模板操作说明](https://help.aliyun.com/zh/pnvs/user-guide/sms-authentication-service)

检查结果：确认签名名称、模板编号、变量名称均来自当前账号可见的配置，且用途符合本次业务；不要直接复制文章里的示例签名。

## 4. 创建最小权限策略

在 RAM 控制台进入“权限策略”，创建自定义策略，选择 JSON 编辑模式，填写：

```json
{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["dypns:SendSmsVerifyCode", "dypns:CheckSmsVerifyCode"],
    "Resource": "*"
  }]
}
```

保存为便于识别的名称，例如 `SmsVerificationApiAccess`。这是只允许发送和核验的示例策略，不授予 `AdministratorAccess`。这里的 `Resource: "*"` 是因为这两个操作目前不支持资源级授权，不是任意放宽其他云服务权限。[发送 API 授权信息](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)、[核验 API 授权信息](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)

检查结果：策略可保存，Action 只有以上两项；下一步将它授予实际运行程序的身份，创建策略本身不会自动使程序获得权限。

## 5. 为运行环境准备凭据

### 本机开发

在 RAM 中创建专用用户，将上面的策略授予它；确需 AccessKey 时为该用户创建，不使用主账号 AccessKey。在 IDE 的本机非共享运行配置或受限秘密文件中给短信后端进程设置：

```text
ALIBABA_CLOUD_ACCESS_KEY_ID=<专用 RAM 用户的 AccessKey ID>
ALIBABA_CLOUD_ACCESS_KEY_SECRET=<对应的 AccessKey Secret>
```

占位符必须替换，但不要把实际值写进源码、Git、共享 Nacos、截图或终端命令历史。它们是进程环境变量，放进任意 Spring properties 文件不会自动变成 SDK 的环境凭据；由项目启动方式负责注入。

### ECS 运行

在 RAM 创建可信实体为阿里云服务/ECS 的角色，附加同一最小权限策略，再在目标 ECS 实例上授予该角色。后端通过官方 Credentials 工具获取和刷新临时凭据，避免向实例复制长期 AccessKey。

使用 Java SDK 默认凭据链时，系统属性、环境变量等来源可能先于实例角色命中。切换角色后应检查并移除不再使用的旧凭据配置，只给需要调用短信的后端进程注入权限；不要打印凭据或元数据响应来排查。实例元数据的访问与加固配置应按当前 SDK 和实例设置核对。[Java 凭据配置](https://help.aliyun.com/zh/sdk/developer-reference/v2-manage-access-credentials/)

检查结果：确认策略绑定到预期用户或角色，运行方式只会选中预期凭据来源。权限准备完成不等于后端 SDK 已正确初始化，下一步必须在项目内验证。

## 6. 回到项目后还要完成什么

按项目实现文档设置 SDK、签名、模板、用途、发送上限、超时及开关，再通过后端少量发送到自己的测试号码。记录发送/核验状态和账单，不保存真实验证码、云凭据或 Token。

云核验通过只表示验证码校验结果通过，不会替你创建用户、绑定手机号、消费本地挑战或签发登录令牌。项目仍需验证用途与用户绑定、一次性消费、过期/重放拒绝、并发与限流、登录会话和改密撤销。核验 API 的 `Code=OK` 仅表示请求处理成功，真正验证码结果需检查 `Model.VerifyResult=PASS`。[核验返回值说明](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)

尚未实际发送或核验时，只能记为“控制台与权限准备完成”，不能宣称注册登录功能已通过验收。
