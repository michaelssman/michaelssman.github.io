# 会话家族

会话家族，就是一次 App 登录产生的 Refresh Token，以及它后来换出来的所有新 Refresh Token。 Token 会换，但这串记录的 family_id 不变。

比如，你在手机上用密码登录：

首次登录：后端创建家族 A，发给 App Access Token 和 Refresh Token R1
第一次刷新：App 用 R1 换到新的 Access Token 和 R2，R1 作废
第二次刷新：App 用 R2 换到新的 Access Token 和 R3，R2 作废

R1 → R2 → R3 都属于家族 A。你在平板上再登录一次，即使是同一个账号，也会创建另一个家族 B。家族代表一次登录，不代表整个账号，也不是设备 ID。

### 为什么要把它们归成一家？

- 识别旧 Token 被再次使用。 假如 R1 已经换过一次，后端又收到 R1，它无法确定是 App 重复提交还是凭据泄露，就撤销家族 A。即使 R3 是最新的，也不能再用来刷新；平板的家族 B 不受影响。
- 控制退出范围。 手机退出时，后端只撤销这次登录所属的家族；设置或重设密码则是账号级操作，会撤销该账号的所有移动刷新会话。普通退出不会立即作废已签发的 Access Token，App 自己要把两种 Token 都清掉。
- 限制登录能续多久。 家族默认从首次登录起有效 30 天。每次刷新只是换凭据，不会把这 30 天重新计时。

### App 怎么用？

App 不用传 familyId。需要刷新时，向网关发 POST /user/auth/mobile/token/refresh，请求体只传手里最新的 Refresh Token：

```json
{
  "refreshToken": "<最近一次登录或刷新返回的 refreshToken>"
}
```

成功后，把本地的 Access Token 和 Refresh Token 一起替换。后端根据 Refresh Token 的摘要找到家族。同一时间如果多个业务请求都需要刷新，只发一次刷新请求，其余请求等新 Token；否则第二个请求可能把本次登录当成旧 Token 重放而撤销。

对应实现：MobileAuthServiceImpl.java。
