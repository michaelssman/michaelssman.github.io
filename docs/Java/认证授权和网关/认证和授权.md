# 认证和授权

## 认证

认证即用户访问系统资源时系统要求验证用户的身份信息。

- 认证通过，由认证服务向给用户颁发令牌，用户拿着令牌去访问系统的资源。
- 未认证则需要去登录。

## 授权

用户**认证通过后**去访问系统的资源，系统会判断用户是否拥有访问资源的权限。

## Spring Boot 3.3.7 当前认证边界

当前项目把“用户凭据认证”“Token 签发”“Bearer Token 验证”拆成不同职责：

- 项目自有登录接口把凭据交给 `AuthenticationManager`，不在 Controller 中自行拼认证结论。
- 登录成功后由共享 `JwtEncoder` 使用 RSA 私钥签发 Token。
- Spring Authorization Server 负责 OAuth2/OIDC 协议端点和 JWKS。
- Gateway 和每个可直连资源服务都启用 OAuth2 Resource Server，只持有公钥验签能力。
- 身份从标准 `SecurityContext` 获取，不信任客户端可伪造的身份 Header。
- 注册、登录必须按 HTTP 方法和完整路径精确放行，不能使用 `/user/**` 或 `/**`。
- 密码只保存 BCrypt 哈希；日志、异常响应、DTO `toString()` 都不能输出明文密码或 Token。

授权码网页登录需要会话，纯 Bearer API 可以无状态。项目存在多条 `SecurityFilterChain` 时必须设置明确顺序：授权服务器端点优先匹配，普通应用链随后处理。

完整代码边界与验收记录见 [hhjava 认证授权与配置安全整改实战](./hhjava认证授权与配置安全整改实战.md)。
