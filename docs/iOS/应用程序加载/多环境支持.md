# 多环境支持

多环境通过不同配置复用同一套代码，例如切换服务地址、功能开关和应用名称。TestFlight 是测试分发渠道，上传到 TestFlight 不会自动切换应用使用的服务环境。

## Xcode 构建配置

| 概念 | 用途 |
| --- | --- |
| Project | 组织源代码、资源、构建设置和多个 Target |
| Target | 定义要生成的产品，例如 App、扩展或测试包，以及构建所需的文件和步骤 |
| Build Settings | 编译、链接、签名等具体设置 |
| Build Configuration | 一组命名的构建设置，例如 Debug、Release，也可增加环境配置 |
| Scheme | 指定 Run、Test、Profile、Archive 等操作使用的 Target 和 Build Configuration |

环境差异主要是参数和资源时，可在同一 Target 下使用不同的 Configuration 与 Scheme。需要测试版和正式版同时安装时，使用不同的 Bundle ID，并分别配置签名和 App Store Connect 应用记录。Flutter 多环境需按 [iOS flavors 文档](https://docs.flutter.dev/deployment/flavors-ios) 配置 Scheme 和对应的 Configuration。

### 用 xcconfig 管理构建设置

1. 创建 Configuration Settings File（`.xcconfig`），填写需要管理的构建设置，不将它加入 Target 的资源。
2. 在 Project → Info → Configurations 中，为相应 Project／Target 的 Configuration 选择基础配置文件；每处选择一个文件，可通过 `#include "Common.xcconfig"` 复用配置。
3. 同层级 Build Settings 中显式设置的值会覆盖 xcconfig。需要交给文件管理的设置，应移除对应显式覆盖。
4. 需要保留继承值并追加列表项时，使用 `$(inherited)`，例如 `OTHER_SWIFT_FLAGS = $(inherited) -D STAGING`。

参考：[Apple 构建系统](https://developer.apple.com/documentation/xcode/build-system)、[Scheme 配置](https://developer.apple.com/documentation/xcode/customizing-the-build-schemes-for-a-project)、[xcconfig 配置](https://developer.apple.com/documentation/xcode/adding-a-build-configuration-file-to-your-project)。

## fastlane：打包与上传 TestFlight

以下流程在 macOS 本机执行。fastlane 使用内置 action 组织任务：`build_app` 负责原生项目归档和导出，`upload_to_testflight` 负责上传及等待处理。一个 `lane` 是一组命名的操作，可通过命令执行。

### 1. 准备项目和工具

- 安装完整 Xcode，并确认终端使用正确的 Xcode：`xcode-select -p`、`xcodebuild -version`。可在 Xcode → Settings → Locations → Command Line Tools 中选择版本。构建工具须满足 [Apple 当前上传要求](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/)。
- 加入 Apple Developer Program，在 App Store Connect 创建与 App Bundle ID 对应的应用记录。
- 在 Xcode 的 Signing & Capabilities 中配置 Team、证书和描述文件，在 Manage Schemes 中勾选目标 Scheme 的 Shared。通过 Product → Archive 归档，再在 Organizer 中使用 Validate App 验证归档。
- 确认 Archive 使用预期的环境配置。发布配置的 Debug Information Format 应为 `DWARF with dSYM File`，用于生成配套 dSYM；保留每次发布的 `.xcarchive` 和符号文件。参见 [Apple 调试符号说明](https://developer.apple.com/documentation/xcode/building-your-app-to-include-debugging-information)。
- 按 [fastlane 安装指南](https://docs.fastlane.tools/getting-started/ios/setup/) 使用受管 Ruby 环境（例如 rbenv，Ruby 3.3 或更高的受支持版本），确认 `ruby --version` 和 `command -v ruby` 指向该环境。Flutter 项目还需安装项目要求的 Flutter SDK 并完成 iOS 依赖配置。

下文的“执行目录”：原生项目为 `.xcodeproj`／`.xcworkspace` 所在目录；Flutter 项目为 `ios/`。在此目录创建 `Gemfile`：

```ruby
source "https://rubygems.org"
gem "fastlane"
```

执行：

```sh
gem install bundler
bundle install
bundle exec fastlane --version
mkdir -p fastlane
```

将 `Gemfile`、生成的 `Gemfile.lock` 和后文的 `fastlane/Fastfile` 纳入版本管理，后续始终通过 `bundle exec fastlane` 执行。需要升级时使用 `bundle update fastlane`，确认流程可用后保留新的锁文件。

### 2. 配置 App Store Connect API Key

本例使用团队 API Key 认证，无需配置 Apple ID 密码或 App 专用密码：

1. 登录 App Store Connect → Users and Access → Integrations → App Store Connect API。尚未开通 API 时，由 Account Holder 申请访问权限；开通后，由 Account Holder 或 Admin 创建 Team Key。
2. 按用途选择权限：仅上传构建可使用 Developer；需要管理测试信息和测试人员时可选择 App Manager。
3. 保存 Key ID、Issuer ID，下载只能下载一次的 `.p8` 私钥，将它放在仓库外的受限目录中。
4. 在执行目录创建 `fastlane/.env`，将以下占位符替换为实际值。私钥使用绝对路径。

```dotenv
ASC_KEY_ID=你的Key_ID
ASC_ISSUER_ID=你的Issuer_ID
ASC_KEY_PATH="/Users/你的用户名/.config/appstoreconnect/AuthKey_你的Key_ID.p8"
APP_IDENTIFIER=com.example.myapp
```

这些变量由下方 Fastfile 显式读取。`APP_IDENTIFIER` 必须与所选 Scheme 构建出的 App 一致。API Key 用于访问 App Store Connect，项目签名仍需要前一步配置的证书和描述文件。

在项目 `.gitignore` 中忽略本地凭据及打包产物；原生项目和 Flutter 项目都可使用以下规则：

```gitignore
**/fastlane/.env*
!**/fastlane/.env.example
*.p8
*.ipa
*.xcarchive/
*.dSYM/
*.dSYM.zip
**/fastlane/report.xml
```

`.env.example` 仅保存占位符。忽略规则不会取消已经被 Git 跟踪的文件，提交前仍应检查范围。自动构建环境通过密钥管理功能注入这些变量和私钥文件。

参考：[Apple API Key](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api/)、[fastlane API Key 认证](https://docs.fastlane.tools/app-store-connect-api/)。

### 3. 创建 Fastfile

在执行目录创建 `fastlane/Fastfile`。本例提供两个入口：`native_beta` 构建原生项目后上传，`upload_ipa` 上传已经生成的 IPA。Flutter 使用第二个入口。

```ruby
def required_value(value, name)
  UI.user_error!("缺少参数：#{name}") if value.to_s.strip.empty?
  value
end

def required_env(name)
  required_value(ENV[name], name)
end

def connect_api_key
  app_store_connect_api_key(
    key_id: required_env("ASC_KEY_ID"),
    issuer_id: required_env("ASC_ISSUER_ID"),
    key_filepath: required_env("ASC_KEY_PATH"),
    in_house: false
  )
end

default_platform(:ios)

platform :ios do
  desc "上传已有 IPA，并等待 Apple 处理完成"
  lane :upload_ipa do |options|
    upload_to_testflight(
      api_key: connect_api_key,
      app_identifier: required_env("APP_IDENTIFIER"),
      ipa: required_value(options[:ipa], "ipa"),
      skip_waiting_for_build_processing: false,
      skip_submission: true
    )
  end

  desc "构建原生 iOS 项目并上传 TestFlight"
  lane :native_beta do |options|
    project = required_value(options[:project], "project")
    workspace = required_value(options[:workspace], "workspace")
    scheme = required_value(options[:scheme], "scheme")
    build_number = required_value(options[:build_number], "build_number")

    increment_build_number(
      xcodeproj: project,
      build_number: build_number
    )
    ipa = build_app(
      workspace: workspace,
      scheme: scheme,
      export_method: "app-store",
      output_directory: "./build/ios"
    )
    upload_ipa(ipa: ipa)
  end
end
```

- `increment_build_number` 更新指定 Xcode 工程的构建号，会修改相关工程文件；构建前检查版本号与构建号是否符合本次发布计划。
- `build_app` 按 Scheme 的 Archive 配置构建，并返回 IPA 路径。`export_method` 使用 fastlane 当前支持的 `app-store`；底层 Xcode 导出参数可通过 `xcodebuild -help` 查看。
- `skip_waiting_for_build_processing: false` 等待 Apple 处理；`skip_submission: true` 使 fastlane 跳过后续测试分发。App Store Connect 已开启的内部测试组自动分发仍可能生效，若要手动分发，应在该组关闭 Enable automatic distribution。
- 这两个入口均不提交正式 App Store 审核。上传结束后仍需完成第 5 步的状态和分发检查。

参数依据：[构建号](https://docs.fastlane.tools/actions/increment_build_number/)、[build_app](https://docs.fastlane.tools/actions/build_app/)、[upload_to_testflight](https://docs.fastlane.tools/actions/upload_to_testflight/)。

### 4. 选择项目类型执行

每次上传前，使用当前版本下尚未上传过、递增的构建号。下面的工程名、路径、版本号和 `42` 都是示例，需要替换为本次发布值。

#### 原生 iOS 项目

在执行目录运行，将 `MyApp` 和 `MyApp-Production` 替换为实际工程、工作空间和 Shared Scheme：

```sh
bundle exec fastlane ios native_beta \
  project:"MyApp.xcodeproj" \
  workspace:"MyApp.xcworkspace" \
  scheme:"MyApp-Production" \
  build_number:42
```

如果项目只有 `.xcodeproj`，删除 lane 中的 `workspace` 参数读取，将 `build_app` 的 `workspace: workspace` 改为 `project: project`，执行时不传 `workspace:`。

多环境可通过 `fastlane/.env.staging`、`fastlane/.env.production` 覆盖 `APP_IDENTIFIER` 等环境差异，并在命令末尾加 `--env staging` 或 `--env production`。它们只配置 fastlane，实际 App 环境仍由传入的 Scheme 及其构建配置决定。[环境变量加载规则](https://docs.fastlane.tools/advanced/other/#environment-variables)

#### Flutter 项目

在 Flutter 项目根目录执行，使用 `flutter build ipa` 一次完成归档与签名导出：

```sh
flutter pub get
flutter build ipa --release --build-name=1.2.0 --build-number=42
```

产物位于 `build/ios/archive/` 和 `build/ios/ipa/`。确认构建成功且生成了本次 IPA，然后进入 `ios/` 上传，将路径替换为实际 IPA 的绝对路径：

```sh
cd ios
bundle exec fastlane ios upload_ipa \
  ipa:"/绝对路径/MyFlutterApp/build/ios/ipa/实际文件名.ipa"
```

已配置 flavors 的项目，构建时添加 `--flavor production` 等实际 Scheme 名；上传时使用对应 `.env.production` 并添加 `--env production`。使用 FVM 的项目将 `flutter` 命令替换为 `fvm flutter`，保持项目 SDK 版本一致。

`--build-name` 对应用户看到的版本号，`--build-number` 对应构建号；也可在 `pubspec.yaml` 中维护 `version: 1.2.0+42`。这条流程不再调用 `build_app`，也不将清理缓存作为每次发布的固定步骤。[Flutter iOS 发布指南](https://docs.flutter.dev/deployment/ios)

### 5. 验证与分发

1. 在 App Store Connect → 应用 → TestFlight 中核对 Bundle ID、版本号和构建号，确认构建已处理完成；按实际加密用途填写必要的出口合规信息。
2. 内部测试：将构建加入内部测试组，并确认测试人员能安装指定构建。若使用自动分发，检查对应组和成员设置。
3. 外部测试：填写测试说明及必要审核信息，选择外部测试组并提交 TestFlight 审核；首个构建需要审核，后续构建也可能需要审核，获准后再分发。
4. 正式上架：在 App Store Connect 创建或选择正式版本，选用已验证的构建，补齐资料并提交 App Review。无需为了正式提审重新上传相同构建。

上传成功、处理完成、测试者可安装和正式上架是不同状态，应分别确认。保留本次构建产物及日志；第三方崩溃平台需要的符号表应来自同一归档。

参考：[Apple TestFlight 流程](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)、[内部测试组](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers/)、[选择提审构建](https://developer.apple.com/help/app-store-connect/manage-builds/choose-a-build-to-submit/)。
