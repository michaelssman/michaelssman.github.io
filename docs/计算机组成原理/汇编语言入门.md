# 汇编语言入门

在高级语言里，一句 `print` 就能输出文本。换到汇编，要先说明往哪里写、从哪个地址取数据，以及写多少字节。本篇跟着一个 Linux x86-64 的 Hello World，读懂寄存器、内存地址和跳转。视频来源为大白讲技术的[《第 22 集：汇编语言》](https://www.douyin.com/video/7709546125417581858)。

## 汇编和机器码是什么关系

CPU 执行机器码。汇编用 `mov`、`dec`、`syscall` 等助记符表示机器指令，还允许用名字表示地址。一条普通汇编指令通常对应一条机器指令。标签和声明数据的伪指令则由汇编器处理。

以 C 的典型构建过程为例，预处理器展开宏和头文件，编译器生成目标架构的指令，汇编器生成目标文件，链接器解析符号引用并生成可执行文件。

视频从 1947 年 Kathleen Booth 参与的 ARC 计算机讲起。今天仍能在开机引导、视频编解码和加密算法的性能关键循环中看到手写汇编。调试崩溃时，反汇编还能把出错地址的机器码还原为指令，帮助判断程序当时在访问什么。

读汇编要先看架构。苹果 M 系列使用 Arm 架构，A64 指令固定为 4 字节。x86-64 的指令长度可以是 1 至 15 字节。还要看操作系统，同一条 `syscall` 指令所使用的调用号和参数约定取决于平台。下文使用 **Linux x86-64 和 NASM 语法**。[Arm A64 指令集说明](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/the-a64-isa-and-compilers) · [Intel 架构手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)

## 跟着一次输出读指令

把下面的程序保存为 `hello.asm`。先看 `_start` 下的四条 `mov`。按 NASM 的书写顺序，左边是目的操作数，右边是来源。前两个 `1` 含义不同，放进 `rax` 选中写操作，放进 `rdi` 选中标准输出。

```nasm
section .data
    msg db "Hello, World!", 10
    len equ $ - msg

section .text
global _start
_start:
    mov rax, 1       ; Linux x86-64 的 write 系统调用号
    mov rdi, 1       ; 参数 1：标准输出的文件描述符
    mov rsi, msg     ; 参数 2：字符串起始地址
    mov rdx, len     ; 参数 3：字节数
    syscall

    mov rax, 60      ; exit 系统调用号
    xor rdi, rdi     ; 退出状态为 0
    syscall
```

**数据放在哪里？** 内存按字节编址，`msg` 标记第一个字节的位置。`.data` 放有初值的数据，`.text` 放要执行的指令，另一个常见的节 `.bss` 为未显式给初值的静态数据预留空间。`db` 写入字符串及换行字节（十进制 10）。`$ - msg` 用当前位置减去起点，得到 14 字节。`equ` 在汇编时给这个值取名，无须另分配一个变量保存长度。[NASM 的数据与常量声明](https://www.nasm.us/doc/nasm03.html) · [NASM 的节定义](https://www.nasm.us/doc/nasm08.html)

**怎样区分地址和内容？** 在 `mov rax, 1` 中，`1` 是直接写在指令里的数，称为立即数。`mov rsi, msg` 把地址放入寄存器，供内核读取。如果写成 `mov rsi, [msg]`，CPU 会读取从该地址开始的 8 字节，把字符串的前 8 个字节当作一个数装入 `rsi`。方括号改变了操作的含义。

**为什么同一个寄存器有好几个名字？** 寄存器是 CPU 内部直接参与运算的存储位置。传统 x86-64 有 16 个 64 位通用寄存器。以 `rax` 为例，`eax` 指低 32 位，`ax` 指低 16 位。其中 `ah` 指第 8 至 15 位，`al` 指最低 8 位。读到这些名字时，要同时看数据宽度和它们共享的位。[Intel 架构手册，第 1 卷](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)

**为什么输出之后还要退出？** 第一次 `syscall` 相当于请求内核执行 `write(1, msg, 14)`。调用返回后，CPU 会继续执行后面的指令。示例从 `_start` 直接进入，没有语言运行时替它收尾，因此用第二次 `syscall` 显式退出。`xor rdi, rdi` 将每一位与自身异或，结果全为零，正好用作成功退出的状态码。[Linux x86-64 系统调用表](https://github.com/torvalds/linux/blob/master/arch/x86/entry/syscalls/syscall_64.tbl) · [Linux 内核的寄存器传参约定](https://github.com/torvalds/linux/blob/master/arch/x86/entry/entry_64.S)

## 汇编、链接和验证

在装有 NASM 和 GNU 链接器 `ld` 的 **x86-64 Linux** 终端中，进入 `hello.asm` 所在目录后运行。使用 Apple 芯片 Mac 时，可在已有的 x86-64 Linux 环境中练习这份示例。

```sh
nasm -f elf64 hello.asm -o hello.o
ld -e _start -o hello hello.o
./hello
echo $?
```

`hello.o` 是 ELF 目标文件，`-e _start` 指定可执行程序的入口。预期终端先显示一行 `Hello, World!`，再显示上一个程序的退出状态 `0`。

## 改成连续打印五次

保留前面的数据定义和退出代码。在 `_start:` 后面、第一条 `mov rax, 1` 前面插入以下两行，让计数器只初始化一次。

```nasm
    mov rbx, 5
print_again:
```

在第一次 `syscall` 后面、`mov rax, 60` 前面加上递减和跳转指令。

```nasm
    dec rbx
    jnz print_again
```

每输出一次，`dec` 就把计数器减一，并更新标志寄存器 `RFLAGS` 中的零标志 `ZF`。第一次从 5 减到 4，`ZF=0`，`jnz` 跳回 `print_again`，CPU 的指令指针 `RIP` 随之转到循环开头。第五次从 1 减到 0，`ZF=1`，程序顺序执行退出代码。重新汇编、链接并运行，即可用输出的五行文字验证循环次数。类似地，`cmp` 可以先比较两个值，再由条件跳转选择执行哪一段代码。
