# 模型角色与回退链配置指南

其核心设计理念是**按用途路由**：让不同的模型去处理最适合它们的任务，从而在效果、速度和成本之间取得最佳平衡。

## 一、 模型角色详解 (Model Roles)

给不同的工作任务分配不同的“专家”。你不需要在每次对话时手动切换模型，OMP 会根据当前任务自动选择预设好的角色模型。

| 角色 (Role)   | 核心用途与区别                                               | 配置建议                                                     |
| :------------ | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **`default`** | **主对话模型**。用于处理大多数常规、交互式的对话任务。       | 选择综合能力最强、最均衡的模型，作为日常工作的主力。         |
| **`smol`**    | **小型/快速/廉价模型**。专为对速度和成本敏感的轻量级任务设计，如后台处理、代码补全等。 | 优先考虑成本低、响应快的模型，例如 Haiku 或 GPT-mini 系列。  |
| **`slow`**    | **重型推理模型**。用于处理需要深度“思考”的复杂任务，如难题分析、代码审查等。 | 选择推理能力顶尖的模型，例如 Opus 或 GPT-5.5，以应对高难度挑战。 |
| **`vision`**  | **视觉/图像分析模型**。专门用于处理和理解图像输入，例如阅读截图、分析图表等。 | 必须选择一个**支持视觉输入**的多模态模型。                   |
| **`plan`**    | **架构/规划模型**。在“Plan Mode”下使用，帮助你在写代码前进行架构设计和任务规划。 | 建议与 `slow` 使用相同的强推理模型，或专门选择擅长规划的模型。 |
| **`commit`**  | **提交信息生成模型**。专门用于自动生成 Git 提交信息和变更日志。 | 这是一个可以“轻松省钱”的角色，用 `smol` 级别的小模型就足够了。 |
| **`tiny`**    | **轻量级后台任务模型**。用于会话标题生成、内存管理等非常轻量的后台工作。 | 如果未设置，会自动回退到 `smol` 角色。                       |
| **`memory`**  | **内存管理模型**。专门处理与内存相关的后台任务。             | 如果未设置，会自动回退到 `tiny` 角色。                       |
| **`task`**    | **子代理/任务委派模型**。当主代理需要将任务拆分并委派给子代理时使用。 | 适合选择一个能力均衡的模型，例如 Sonnet 系列。               |
| **`advisor`** | **后台顾问模型**。在每个回合中提供额外的审查和建议，但这会**成倍增加调用次数**。 | 选择一个独立的强推理模型，默认情况下它不会继承你的主对话模型。 |
| **`widget`**  | **交互式小组件模型**。用于驱动 OMP 界面中的交互式小组件（Widget）运行。 | 通常选择轻量快速的模型即可。                                 |
| **`judge`**   | **评判/裁决模型**。用于对回答或代码进行质量评估和裁决（Judgment）。 | 可以选择 `tiny` 或普通的聊天模型。                           |

---

## 二、 回退链机制 (Fallback Chains)

`fallbacks:deepseek-flash` 和 `retry-fallback` 是**模型请求失败时的自动降级机制**。

*   **作用**：当某个模型因请求过载（如返回 429 错误）、权限问题或持续失败时，OMP 会自动将当前任务按顺序交给 `fallback` 链中的下一个模型处理，确保任务不中断。
*   **选择**：通常无需手动干预。如果希望为 `deepseek-flash` 配置更稳健的备用模型，可以在配置文件中调整 `retry.fallbackChains` 的顺序。

---

## 三、 配置选择建议

对于绝大多数用户，**保持默认的自动选择即可**，OMP 会在你登录提供商后自动分配可用的模型。

当你希望获得更**可预测的质量、延迟或成本**时，可以手动配置。一个推荐的入门策略是：

1.  **稳住核心**：为 `default`、`slow` 和 `plan` 角色分配最强的前沿模型。
2.  **控制成本**：将 `smol`、`commit` 和 `tiny` 这类后台任务角色分配给快速且便宜的小模型。
3.  **按需启用**：`advisor` 角色会显著增加调用量，除非你明确需要每轮审查，否则可以保持关闭。
4.  **特殊能力**：如果你的主模型不支持图片，记得为 `vision` 角色单独配置一个多模态模型。
